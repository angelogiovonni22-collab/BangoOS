# B.O.S. Blueprint Training-Data Governance

B.O.S. must own or hold explicit commercial training rights for every plan used to train Production Blueprint models. A permissive code license does not automatically grant commercial rights to upstream datasets or derived checkpoints.

## Allowed sources

- Floor plans generated by the versioned B.O.S. synthetic generator.
- Bango Construction plans that Bango Construction owns and has approved for model training.
- Customer plans only after explicit, separately recorded opt-in permission that identifies model training as a use.
- Third-party datasets whose license and checkpoint provenance have passed documented commercial review.

## Prohibited sources

- Customer uploads collected through ordinary Blueprint operations without separate training consent.
- Private Mitchell benchmark sheets; they remain holdout acceptance evidence and must not enter training.
- Datasets or checkpoints restricted to research, education, evaluation, or noncommercial use.
- Plans with unknown ownership or license provenance.

## Dataset controls

Every dataset release must have a version, deterministic manifest, train/validation/test split, per-file SHA-256 hashes, generator or source identity, license classification, and a declaration of whether customer data is present. Training jobs must pin the manifest hash and model code revision so a Production checkpoint can be reproduced and audited.

Synthetic output is written outside source control. Generated samples and model weights must never be committed to the BangoOS repository.

## Acceptance boundary

Training metrics alone never authorize a model for Production. A candidate must pass the automated Blueprint Production Acceptance Standard, preserve deterministic source evidence, and pass a human source-versus-model review on held-out plans including Mitchell page 2. Failed or ambiguous learned inference must leave the deterministic Building Graph unchanged.
